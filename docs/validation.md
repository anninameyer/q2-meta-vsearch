including intentionally empty input/output fixtures.

Existing environments were not modified: a real wheel was installed into a
temporary target directory, discovered through `PYTHONPATH`, and CLI caches were
redirected to a temporary prefix. Both upstream and fork plugin registrations
were loaded by QIIME 2's actual plugin manager.

The upstream plugin is a test-only dependency for the coexistence check, not a
runtime dependency of q2-meta-vsearch.

## Target installation and tests

On Linux x86-64, create a **new** environment from the provided release-package
specification. This environment file has not yet been solved or executed:

```bash
conda env create -f environment-files/q2-meta-vsearch-2026.10-linux-64.yml
conda activate q2-meta-vsearch-2026.10
python -m pip install . --no-deps --no-build-isolation
qiime dev refresh-cache
qiime meta-vsearch --help
qiime vsearch --help
qiime meta-vsearch align-closed-reference --help

python -m pytest q2_meta_vsearch/tests/test_plugin_setup.py \
  q2_meta_vsearch/tests/test_cluster_features.py -x --tb=short -q
python -m pytest q2_meta_vsearch/tests/test_align.py -x --tb=short -q
python -m pytest q2_meta_vsearch/tests \
  --ignore=q2_meta_vsearch/tests/test_examples.py --tb=short -q
```

For another platform, use its official patched 2026.10 environment rather than
the Linux file. Upstream's released platform files are available in
[QIIME 2 distributions](https://github.com/qiime2/distributions/tree/dev/2026.10/qiime2/released).
Install the local repository using the commands above after activating that new
environment. Keep q2-vsearch installed to test coexistence.

The optional upstream remote-data test can be run separately:

```bash
python -m pytest q2_meta_vsearch/tests/test_examples.py --tb=short -q
```

For existing older environments, clone them before installing the fork:

```bash
conda create -n q2-meta-vsearch-2024.10 --clone qiime2-amplicon-2024.10
conda activate q2-meta-vsearch-2024.10
python -m pip install . --no-deps
qiime dev refresh-cache
python -m pytest q2_meta_vsearch/tests \
  --ignore=q2_meta_vsearch/tests/test_examples.py --tb=short -q
```

## Synthetic runtime and memory observations

These are one-run software checks on macOS using one x86-64 VSEARCH 2.22.1
thread, not biological benchmarks or scalability claims. Python import time is
excluded. Child-process RSS excludes parent Python memory.

| Fixture | Queries × references | VSEARCH wall time | Alignment + validation | Child peak RSS |
| --- | --- | --- | --- | --- |
| basic, 200 bases | 2 × 3 | 0.094 s | 0.184 s | 8.84 MiB |
| precision, 3,000 bases | 1 × 2 | 0.150 s | 0.178 s | 77.20 MiB |

Exact measurements and fingerprints are stored in
[`synthetic-profile-2026-11-08.json`](synthetic-profile-2026-11-08.json).
Run each case in a fresh process to keep memory high-water marks independent:

```bash
python scripts/profile_synthetic_alignment.py \
  --case basic --output /tmp/meta-vsearch-profile-basic
python scripts/profile_synthetic_alignment.py \
  --case precision --output /tmp/meta-vsearch-profile-precision
```

Choose new output paths if these already exist. The script saves the actual
evidence, BLAST6 projection, and timing/memory report. It does not generate
biological results.

## Changes and next milestone

The complete package and its existing tests/data were moved from `q2_vsearch/`
to `q2_meta_vsearch/`. All legacy actions remain registered. Self-plugin lookups,
examples, template metadata, assets, coverage configuration, recipe imports,
entry points, and version-file paths now use the new identity. Chimera statistics
types/formats are independently namespaced; this necessary public type-name
change prevents conflicts with upstream and leaves their TSV contents unchanged.

New implementation files are `_align.py`, `_alignment_evidence.py`, the alignment
type/formats in `_type.py` and `_format.py`, and the action registration in
`plugin_setup.py`. New tests and synthetic fixtures live in `tests/test_align.py`
and `tests/data/alignment/`. Packaging excludes generated bytecode. The README,
this report, the evidence-schema documentation, dedicated target environment,
and profiling script cover installation and inspection.

Changed paths, grouped:

- Renamed all 57 original files in `q2_vsearch/` to `q2_meta_vsearch/`, preserving
  existing algorithms, tests, fixtures, and assets.
- Updated `pyproject.toml`, `conda-recipe/meta.yaml`, `.copier-answers.yml`,
  `.coveragerc`, `Makefile`, `README.md`, `CHANGELOG.md`, `.github/SUPPORT.md`, and
  `.github/ISSUE_TEMPLATE/6-where-to-go.md` for the standalone identity.
- Added `q2_meta_vsearch/_align.py`, `_alignment_evidence.py`,
  `tests/test_align.py`, and the synthetic `tests/data/alignment/` fixtures.
- Extended `q2_meta_vsearch/_type.py`, `_format.py`, `plugin_setup.py`, and
  `tests/test_plugin_setup.py` for evidence registration and coexistence checks.
- Added `docs/alignment-evidence.md`, `docs/validation.md`,
  `docs/synthetic-profile-2026-11-08.json`,
  `environment-files/q2-meta-vsearch-2026.10-linux-64.yml`, and
  `scripts/profile_synthetic_alignment.py`.

The BLAST6 output is a standard projection constructed from exact userout counts
rather than a second VSEARCH search. Explicit `*` no-hit records preserve valid
BLAST6 output when all queries fail; authoritative `hits.tsv` contains no fake
alignments. Identity tolerance is not exposed as an M2 parameter: all accepted
hits are retained, and exact-best flags always use zero tolerance. Future
near-best reporting can operate on this evidence without changing weight
eligibility. These choices do not alter the stated sequence-evidence principle.

M3 should add a shared reader for schema-1 evidence and an ASV summary using
`FeatureData[SequenceCharacteristics]`. Start with one row per query, exact-best
reference/alignment counts, selected-hit or range statistics, and explicit
matched/no-hit and completeness fields. Keep original IDs as strings. Preserve
the full evidence unchanged. Taxonomy, ecological decisions, and count
aggregation remain later milestones; future unresolved reference selection must
default to stable reference-ID ordering with ambiguity retained.
